# Enhancement Plan: Intelligent Message Processing & Categorization

## Problem Statement
Current Groq summarization produces 1-3 line summaries that are too basic. The system needs:
1. **Rich templated summaries** with structured detail sections
2. **Auto-categorization** of messages by type (planning, meeting, financial, etc.)
3. **Better dashboard** with category filtering and structured views
4. **Workflow routing** — route categorized messages to appropriate tables/actions
5. **Generalization** — work for any use case, not just broker-customer

## Phase 1: Enhanced Groq Summarization Template

### Rewrite `_GROQ_SUMMARY_PROMPT` (broker/main.py)
Replace the broker-specific prompt with a detailed structured output:

```json
{
  "category": "meeting|financial|loan|planning|process|inquiry|update|general",
  "subcategory": "optional finer-grained label",
  "sentiment": "positive|neutral|negative|urgent",
  "intent": "Single sentence: what does this person want/need",
  "detailed_summary": {
    "overview": "2-3 sentences",
    "key_points": ["point 1", "point 2"],
    "decisions": ["any decision or commitment made"],
    "risks_concerns": ["any risks, concerns, blockers mentioned"],
    "next_steps": ["concrete next actions ranked by priority"]
  },
  "entities": {
    "people": ["names mentioned"],
    "dates": ["dates/deadlines mentioned"],
    "amounts": ["monetary amounts"],
    "documents": ["documents referenced"],
    "locations": ["places/addresses"]
  },
  "meeting_suggestion": "when, purpose, duration — or null",
  "reply_suggestion": "professional 1-3 sentence reply",
  "urgency": "low|medium|high",
  "follow_up_required": true/false,
  "tags": ["auto-generated keyword tags"]
}
```

**Changes to `_extract_with_llm()`:** Keep Groq-first fallback with the enhanced prompt. Update the Ollama fallback prompt similarly.

## Phase 3: Category-Specific Workflow Routing

When a message is processed and categorized, route create appropriate records:

| Category | Action |
|----------|--------|
| `meeting` | Auto-create `BrokerMeeting` + ICS invite (existing logic) |
| `financial` | Extract amounts/entities → store in `BrokerVoiceRecording.entities` |
| `loan` | Extract loan details → store with loan-specific fields |
| `planning` | Add to planning board view (list of plan items) |
| `process` | Create process tracking entry with status |
| `inquiry` | Flag for manual review, add to actions list |
| `update` | Store as status update, link to customer if exists |
| `general` | Store as general note, no special routing |

### New `_route_by_category()` function
After extraction, call a routing function that dispatches based on `category`:
- Creates meeting if `meeting_suggestion` is present
- Creates customer record if `customer_name` + phone are new
- Stores entities in structured format

## Phase 5: Generalization

- "Broker CRM" → "Inbox Intelligence"

## Implementation Order

1. **Backend prompt rewrite** — `_GROQ_SUMMARY_PROMPT` with structured output + categories
2. **Database migrations** — Add category/sentiment/tags/entities columns
3. **Model updates** — Add fields to `BrokerVoiceRecording` and `WhatsAppVoiceJob`
4. **Category routing** — `_route_by_category()` function in worker
5. **New dashboard endpoint** — `GET /api/broker/dashboard/categories`
6. **Frontend dashboard rewrite** — Category view, enhanced summary cards, filters
7. **Generalization** — Remove broker-specific language from prompts and UI
